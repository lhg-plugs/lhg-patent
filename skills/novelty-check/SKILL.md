# novelty-check：新颖性/创造性/实用性三性自检

> ⚠️ **合规声明**：本 skill 是**自我审查清单**，不是授权保证，不能直接提交专利申请；
> 检索结果**不保证查全**，三性的最终判断**必须由专利代理人做出**。

> 目标：提交前自己先当一回审查员，把明显的问题拦下来。
> 核心纪律：**自检是"找茬"不是"找补"；找不到茬不等于没茬，只说明你没找到。**

## 1. 何时使用

- 权利要求书+说明书初稿完成，提交代理人之前 → 用本 skill 做最后一轮自检
- 收到审查意见通知书，想自己先理解问题在哪 → 对照第 3 节找对应项
- 做现有技术检索 → 按第 4 节流程走

## 2. 输入与输出

**输入**：`claims.txt` + `description.md` + 技术主题关键词。
**输出**：`novelty.json`（三性逐项自评 + 依据）+ `prior-art.md`（最接近现有技术比对表）。

## 3. 分步方法论：三性逐项自检

### 3.1 新颖性自检——"现有技术里有没有一模一样的？"

逐项权利要求问自己：

1. 有没有一篇现有技术公开了**全部**技术特征？（一篇就够判无新颖性）
2. 有没有**自己**的在先公开？（论文、产品发布、众筹页面、展会演示——**自己的公开也算**）
3. 公开日是否早于申请日？（哪怕早一天也算）

**诚实写法**：`novelty.json` 里写"本次检索（检索式/数据库/日期）未发现公开全部特征的现有技术"，
不写"具有新颖性"——结论让代理人下。

### 3.2 创造性自检——"本领域技术人员容易想到吗？"（最难的一关）

创造性是驳回重灾区。自检三问：

1. **区别特征是什么？**（和最接近现有技术比，你的方案多了/改了什么）
2. **区别特征带来了什么预料不到的技术效果？**（"预料不到"是关键词：
   常规优化、简单叠加、等同替换，一般不算有创造性）
3. **有没有技术偏见/反向教导？**（现有技术是不是"教导人们不要这么做"——
   如果是，你的方案创造性加分）

**加分项清单**（有就写进自评依据）：
- 解决了长期存在的技术难题
- 取得了预料不到的技术效果（数据说话）
- 克服了技术偏见（现有技术明确说这条路走不通）
- 商业成功且与技术特征直接相关（辅助证据）

**减分项清单**（有就老实承认，提前准备答辩）：
- 区别特征只是常规选择（材料替换、尺寸调整）
- 是两项已知技术的简单拼凑，且效果可预期
- 区别仅在于"用计算机实现"（纯软件方案特别注意）

### 3.3 实用性自检——"能不能造出来、用起来？"

相对简单，但别跳过：

1. 说明书的实施例能不能**实际制造**？（缺关键步骤、缺关键参数 = 公开不充分）
2. 技术方案是否违反自然规律？（永动机类直接出局）
3. 是不是纯智力活动规则？（纯商业模式、纯算法无技术效果，实用性/客体有风险）

### 3.4 novelty.json 模板

```json
{
  "新颖性": "本次检索（中国专利数据库+Espaceent，检索式：智能水杯 AND 水温显示，2026-10-11）未发现公开全部技术特征的现有技术；发明人确认申请日前无自行公开。",
  "创造性": "区别特征：温度显示装置集成于杯体外壁。现有技术多为杯盖测温，存在技术偏见（认为外壁集成影响保温）；本方案实测保温性能无显著下降，效果预料不到。",
  "实用性": "实施例给出了完整装配步骤与部件参数，可制造；已做出手板验证功能。"
}
```

**写法要求**：每项写**依据**，不写结论词。每项至少一句话依据，写不出依据 = 这一项没准备好。

## 4. 现有技术检索流程

1. **拆要素**：技术领域 + 核心特征 + 解决的问题，每个要素准备 3~5 个同义词/上位词
2. **构造检索式**：`(特征A OR 同义词) AND (特征B OR 同义词) AND 技术领域`，先宽后窄
3. **跑检索源**（按优先级）：
   - 中国专利全文数据库 → Espacenet / Google Patents → 非专利文献（论文/产品手册/众筹/电商页面）→ 行业标准
4. **比对建表**（`prior-art.md`）：每篇最接近文献写清"公开了什么 / 与本方案的差异"
5. **写诚实声明**：覆盖范围 + "检索不保证查全，未发现不等于不存在"

**检索死角提醒**（最容易漏的）：
- **自己的公开**：发过的论文、卖过的产品、做过的路演——都算现有技术
- **外文文献**：只查中文库等于只查了一半
- **非专利文献**：产品说明书、众筹页面经常比专利更早公开
- **在先申请**：别人已提交未公开的申请也可能成为对比文件（保密审查期）

## 5. 反模式

1. **自检变自夸**："本发明具有突出的实质性特点和显著的进步"——这是结论不是自检。
   自检要写的是"区别特征是什么、效果数据是多少"，让事实自己说话。
2. **检索只查专利库**：竞争对手的产品手册、电商详情页可能早就公开了你的"发明点"。
3. **用"应该没问题"代替检索**：创造性判断不做检索支撑，等于闭眼签字。
4. **隐瞒最接近现有技术**：自检时发现一篇很接近的文献，想着"代理人/审查员不一定查到"——
   审查员的信息检索能力远超想象，隐瞒只会让答辩更被动。提前准备区别论述才是正道。
5. **把实用性当走过场**：实施例写不出来"怎么做"，说明技术方案本身还没想清楚，回去补交底。
6. **申请日后补公开**：申请提交前发产品、发论文——公开一次，新颖性就没了。先申请，后公开。

## 6. 审查意见常见驳回理由速查（提前避雷）

| 驳回理由 | 审查员在说什么 | 自检时怎么避 |
|---|---|---|
| 不具备新颖性 | 找到一篇公开了你全部特征的文献 | 检索时重点看"最接近文献"，差异特征至少留一个 |
| 不具备创造性 | 区别特征是常规手段/简单拼凑 | 准备"预料不到的技术效果"数据，写进说明书 |
| 公开不充分 | 实施例讲不清怎么做 | 实施例按"装配步骤+参数"写，找个外行读一遍能否复现 |
| 得不到说明书支持 | 权利要求特征说明书没写 | 权利要求每个特征反查说明书，PAT-DSC 系列规则辅助 |
| 权利要求不清楚 | 有相对词/引用混乱/并列择一写错 | 跑 patent_audit.py，PAT-CLM 系列清零 |
| 缺乏单一性 | 一件申请塞了两个发明 | 产品和方法分开布局，或准备分案申请 |

**收到审查意见通知书后**：先对照上表定位问题类型，再决定是答辩（争辩+证据）
还是修改（限缩范围）。修改不许超出原说明书公开范围——这就是说明书要写"宽"的原因。

## 7. 自检与反馈

**质检门**（提交代理人前逐项打勾）：

- [ ] novelty.json 三项每项都有**依据**（不只是结论）
- [ ] 最接近的 3 篇现有技术已列入 prior-art.md 并写清差异点
- [ ] 检索覆盖了专利库 + 非专利文献（至少写清覆盖了哪些源）
- [ ] 诚实声明已写（不保证查全、未发现≠不存在）
- [ ] 发明人确认申请日前无自行公开（论文/产品/路演）
- [ ] 创造性的区别特征与预料不到的效果已准备好数据/论述
- [ ] patent_audit.py 跑过，blocker 清零
- [ ] 全文末尾有合规声明（须经专利代理人复核）

**标准冒烟用例**：用 fixtures/good 跑审计期望零 blocker；用 fixtures/bad 跑期望命中 PAT-NOV-001（三性清单缺失）。

**一键提 issue**：三性判断拿不准的边界场景，以 `[novelty] <一句话场景>` 为标题提交到
https://github.com/lhg-plugs/lhg-patent/issues（注意不要在 issue 里公开你的技术细节）。
