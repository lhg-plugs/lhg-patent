# /lhg-patent:patent —— 专利撰写一条龙

用户输入在 `$ARGUMENTS` 中：技术方案一句话（如"一种带水温显示的智能水杯"）。缺省则先问用户要技术方案。

> ⚠️ **合规声明**：本流程产出的是**撰写辅助草稿**，**不能直接提交专利申请**，必须经专利代理人/代理机构复核后才能使用；现有技术检索结果不保证查全。

## 流程

### 1. 交底书挖掘（加载 disclosure）
和用户做一轮技术访谈，输出 `disclosure.md`：
- 技术特征拆解：把方案拆成最小技术特征清单
- 三要素：技术问题 → 技术手段 → 技术效果（每个特征回答"解决了什么问题"）
- 必要技术特征：标出解决核心问题的最小特征集合 → 写入 `features.json`

### 2. 权利要求书（加载 claims-draft）
按"独立权利要求（上位概括，只写必要技术特征）→ 从属权利要求（梯度限缩）"撰写 `claims.txt`：
- 独立权利要求格式：前序部分（已知技术）+ "其特征在于" + 特征部分（发明点）
- 从属引用只能引用在前编号，不许断裂/反向引用
- 保护范围检查：独立权利要求限定不过多，细节下沉从属

### 3. 说明书（加载 claims-draft 第 5 节）
组织 `description.md`：技术领域 → 背景技术 → 发明内容 → 附图说明 → 具体实施方式：
- 附图标记全文统一，附图说明中逐一定义
- 术语全文一致（一套说法用到底）
- 实施例至少一个，证明"能够实现"

### 4. 新创性自检（加载 novelty-check）
输出 `novelty.json`：新颖性 / 创造性 / 实用性三项逐项自评，
每项写"检索/分析依据"，不许写"应该没问题"。

### 5. 跑确定性审计
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/patent_audit.py --target <工作目录> --format text
```
blocker（引用断裂、附图标记断裂）清零；warning 要么修要么写理由。

## 输出
`disclosure.md` + `claims.txt` + `description.md` + `novelty.json`，
每份文件末尾附合规声明："本稿为 AI 辅助草稿，须经专利代理人复核后方可提交申请。"

## 硬规则
- 任何情况下不许说"可以直接提交"——必须经专利代理人复核，这是红线。
- 检索结论不许用"查全了""没有现有技术"这类绝对表述，用"本次检索未发现"。
- 为清零改审计规则 → 作弊，不许。
